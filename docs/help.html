Overview

MergeFiles compares two or three files or folders side by side and helps you merge them. Changed blocks are tinted, the characters that changed inside a block are highlighted more strongly, and curved lines in the gutter join each block to its counterpart.

ColourMeaning
GreenInserted: text only on this side.
OrangeRemoved: text only on the other side (shown on the side that has it).
PurpleChanged: different on both sides.
RedConflict (three-way): both sides changed the same lines differently.

Press F1 anywhere to open the help topic for what you are doing. In a dialog box, F1 opens the topic for that dialog.

Starting a comparison

  • File > New Two-Way Comparison (Ctrl+N) or New Three-Way Comparison (Ctrl+Shift+N) asks for the files. New Folder Comparison (Ctrl+D) asks for folders; a .zip or .tar archive can be given in place of a folder.
  • Drop two or three files or folders on the window. Dropping one file on a pane replaces that pane's file.
  • From the command line: MergeFiles.exe left right or MergeFiles.exe left ancestor right. A .patch or .diff file opens as a patch, and a .mfcmp file opens as a saved comparison.

What opens depends on the files: text files open as a text comparison; Word, Excel, PowerPoint, OpenDocument and RTF files open as a comparison of their text; images open as an image comparison; other binary files open as a byte comparison; folders and archives open as a folder comparison.

Two-way comparison

The two files are shown side by side with a path bar above each. Scrolling is synchronized: corresponding lines stay level. The overview strips at the edges show the whole file; click one to jump there. With View > Line Detail, the current line of each file is shown one above the other at the bottom, which makes small changes in long lines easy to see.

The status bar shows the encoding and line endings of the current pane, the number of removals, insertions and changes, and the caret position.

See also: Editing and merging, Comparison options.

Three-way merge

A three-way comparison shows two changed versions (left and right) and their common ancestor in the middle. The middle file is the merge target: changes made on only one side can be taken automatically, and conflicts (red) need a decision.

  • Merge > Automatic Merge takes every change made on only one side, and identical changes made on both.
  • Click the arrow on a block, or use Alt+Right / Alt+Left, to take a side's version of a conflict.
  • Edit the middle file directly where neither side is right, then mark the lines as resolved (Merge > Mark Resolved).
  • Next/Previous Conflict skips the blocks that merged cleanly.

Editing and merging

Every pane can be edited in place (unless the file is read-only). Text can be dragged between panes. Each block has merge arrows in the gutter that copy it to the other side; Replace Right/Left copies a whole file. Undo and redo cover typing, merges and replacements. Indent and un-indent selected lines with Tab and Shift+Tab.

The comparison is updated as you type. Compare Again (F5) re-reads nothing; it recomputes the differences with the current options.

Find, replace and go to line

Edit > Find (Ctrl+F) and Replace (Ctrl+H) search the current pane, optionally matching case or whole words, or only within the selection. F3 and Shift+F3 repeat the last search. Go To Line (Ctrl+G) moves the caret to a line of the current pane.

Bookmarks and comments

Ctrl+F2 sets or removes a bookmark on the caret's line; F2 and Shift+F2 move between bookmarks. Edit > Bookmark Comment (Ctrl+Shift+F2) bookmarks the line and attaches a note, for example a question for a reviewer.

A comment is shown as a yellow tag at the end of its line and in the status bar when the caret is on that line. It moves with the line as you edit, and it is included in reports, printouts and comparison archives.

Synchronization links

When the comparison pairs the wrong lines (for example after a large reorganisation), put the caret on corresponding lines in each pane and choose Synchronize the Current Lines. The files are then compared separately above and below the link, shown as a dotted blue line.

Word, Excel and other documents

Word (.docx), Excel (.xlsx), PowerPoint (.pptx), OpenDocument (.odt, .ods, .odp) and RTF files are compared by their text. The text is read-only, and saving changes back into the documents is not supported. It is laid out like this:

  • one paragraph per line, and one table row per line with the cells separated by tabs;
  • each worksheet starts with a [Sheet: name] line and each slide with [Slide n]. Spreadsheet cells show their values (formulas are not shown);
  • Word footnotes and endnotes follow the body. Deleted tracked changes and comments are left out.

In a folder comparison with the Thorough mode, documents are compared by their text too. Two documents that differ only in how they were saved count as identical.

Old binary formats (.doc, .xls, .ppt) and PDF files are not supported.

Encodings and line endings

MergeFiles detects UTF-8 and UTF-16 (with or without a byte order mark) and otherwise uses the system code page. A file is saved in the encoding it was read with; Current Pane > Encoding changes that. Reload As re-reads a file with a chosen encoding (for example Shift-JIS). Line endings (CR LF, LF, CR) are kept per line, and differences in line endings are ignored unless you turn that option off.

Folder comparison

Two or three folder hierarchies are listed as one tree with a status for every file and folder: identical, different, only on one side, or (three-way) changed on the left, on the right, the same on both, or in conflict. The comparison runs in the background; Stop (Esc) ends it early.

Select a file to see its comparison in the lower half. Press Enter or double-click to open an image, binary file or archive in a tab of its own. The Show buttons hide identical items or items that exist on one side only.

How files are compared is set in Options > Folders and Images: by size and date (quick), byte by byte, or thoroughly as text with the comparison rules.

Synchronizing and merging folders

Copy to the Right/Left makes the other side match the selected items. Copying a missing item deletes it from the other side, and deleted items go to the Recycle Bin. In a three-way folder comparison, Automatic Merge applies to the ancestor folder every change made on one side only. Files changed on both sides are merged line by line when that gives no conflicts. Everything else is left for you.

Select Files

Selects the items matching a wildcard pattern (for example *.cpp;*.h), limited to the statuses you tick, so that one copy or delete command can act on all of them.

Archives (.zip, .tar)

A .zip, .jar, .war, .ear, .nupkg, .vsix, .tar, .tgz or .tar.gz file can be used wherever a folder can. Compare two archives, or an archive with a folder to check what changed since the archive was made. Archive contents are compared like files on disk.

  • Archives are read-only: you can copy from an archive to a folder (extracting), but not into an archive or delete from it.
  • Files shown from inside an archive are temporary copies, removed when MergeFiles closes.
  • An archive inside a folder comparison opens as a folder comparison of its own when you press Enter on it.
  • Encrypted entries, and compression methods other than stored and deflate, cannot be read.

Binary files

Files that are not text are shown in hex, 16 bytes per row with their characters, and differing bytes are highlighted. Files up to 1 MB are aligned so that inserted or removed bytes do not make the rest of the file differ.

Images

Two images are shown side by side with a third panel that marks the differing pixels in red. Differing areas are outlined, and Alt+Down / Alt+Up zoom to the next or previous one. Zoom with Ctrl and the mouse wheel, and drag to pan. The colour tolerance is in Options.

Patch files

A unified diff (from git, svn or diff -u) opens as a list of its files and hunks with check boxes. Apply Checked Hunks applies the selected changes to the files under a folder you choose. Each hunk is found near the line its header gives, so lines that moved still apply. Every patched file then opens as a comparison to review and save. Reverse takes a patch back out.

XML

View > Compare as Formatted XML opens a read-only comparison of the two files laid out one element per line, which makes changes in files written on a single line easy to find.

Reports

File > Create Report (Ctrl+E) saves the comparison as:

  • HTML: side by side in the comparison's colours, with changed characters highlighted;
  • HTML slideshow: one difference at a time, with Previous/Next buttons and the arrow keys;
  • XML, for processing by other tools;
  • Unified diff, a patch that other tools can apply.

Choose the whole files, or only the differences with some lines of context around them. A folder report lists the items and their statuses, and can include a report of every file that differs.

Comparison archives

File > Save Comparison Archive saves a whole comparison in one .mfcmp file to send to a colleague. The file holds:

  • the text of every file and its encoding;
  • the comparison options;
  • bookmarks and their comments, resolved lines and synchronization links.

Open it with File > Open Comparison Archive, by dropping it on the window, or by passing it on the command line. A folder comparison archive keeps the results; it opens read-only, and Start compares the folders again as they are now.

Printing

File > Print (Ctrl+P) and Print Preview print the comparison side by side in its colours. Long lines are wrapped, filler marks where the other side has lines, and comments appear under their lines.

Page Setup sets:

  • the header and footer, with the fields {title}, {files}, {date}, {page} and {pages};
  • portrait or landscape;
  • the font size;
  • Print only pages with changes, to save paper.

Comparison options

Options > Options > Comparison sets how lines are compared:

  • whitespace: compared, changes ignored, or ignored entirely;
  • case, and line endings;
  • inserted or removed blank lines;
  • a numeric tolerance, absolute or relative, under which numbers count as equal.

Blocks that differ only in ways you ignore are shown in grey and are not counted as differences.

Rules

Regular expressions for text to leave out of the comparison, such as comments or version-control keywords. Line rules remove matching text within a line. Block rules ignore everything from a begin pattern to an end pattern. A line pairing rule picks the part of each line used to pair changed lines, which helps with files such as translations where one key is followed by different text.

Display

The font and its size, tab width, word wrap, padding lines (which show missing lines as blank rows instead of linking lines), the line detail panel, syntax highlighting, visible whitespace, and the colours used for differences.

Folders and images

How folder comparisons compare files (quick, byte by byte, or thorough), the size above which thorough mode falls back to bytes, which files to include or exclude (wildcards separated by ;, with a trailing \ for folders), and the colour tolerance for image comparisons.

Statistics

View > Statistics counts the lines, changed lines and differences of each file, or the items of each status in a folder comparison.
